# P20 condition inventory scope

This extends the existing V25_TASK_3_1_CURRENT_FUNCTIONAL_CRITERIA.json, not a second rule catalog.

- 23 condition rows separate the owner requirement, necessary witness, current executable/diagnostic behavior, implementation gap and open profile/calibration.
- Eight exact Git blob bindings identify the current n2 and scoped n1 evaluator entrypoints. These are selected-file bindings, not whole-repository source closure.
- The historical functional_review mapping remains under legacy_checker. Old assessment/CI evidence is historical and is not reclassified.
- Private source locations are replaced in the current catalog by aliases. Exact source readback citations stay outside this public repository.
- A runtime subcondition result is not the aggregate criterion. Three evaluators still produce scoped diagnostics with aggregate UNKNOWN; programme additionally maps proven approved-capacity mismatch to FAIL.
- A rejected supplied route is not proof every route is impossible. A missing conservative route witness does not prove an infeasible architectural problem.
- Material/area, source inventory, route access and a sufficient separator certificate do not automatically prove useful living, full programme adequacy or wall necessity.
- Source body width is a bounded study profile. No new numerical quality threshold is introduced.
- Conceptual core evidence is separate from technical/legal stair/lift certification. Out-of-scope is not PASS.

## Executed test design
The catalog validator checks declared source aliases, required condition inventory, exact current evaluator blobs and entrypoint names, no declared new thresholds and no criterion/admission promotion. Human source review, not this structural validator, establishes the meaning of requirement citations. It is not an NLP verifier of every sentence and not a model evaluator.

Synthetic tests call the actual existing capacity helper, route sweep checker, geometric union/counterfactual helper and decision reducer. They do not call the generator, MILP, replay, whole four-assessor pipeline or HTTP. Popen/MILP sentinels prohibit accidental generation during test cases. No private model or report is needed.

## Done boundary
Condition inventory and current implementation mapping tested; this does not complete P21-P25, qualify a design, repair architectural quality, provide raw archive durability, or resolve open calibration. No source/evaluator/gate/budget behavior is changed.

# Development policy

- All future code changes belong in this GitHub repository only. Do not create or edit project code on the user's Mac or in a cloud workspace.
- Read-only inspection of authorized source is allowed for migration. Never upload credentials, databases, personal data, or virtual environments.
- Preserve source provenance. Do not claim the original588 was recovered or that staged adapters are deployed services.
- Current input domain is independently inclusive5..25 metres for W and L. Reject outside values without clamping.
- Unknown mandatory functional evidence is not acceptance and must not appear as a design option. Furniture is internal test evidence only, not output content.
- Current development scope is two units. Six qualified diverse designs are a goal, not an achieved capability.
- Keep experiments, historical evidence, integration status and actual tests distinct. No deployment or source-freeze bypass.
